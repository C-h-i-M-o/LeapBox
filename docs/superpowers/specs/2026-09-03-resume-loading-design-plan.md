# 简历资源加载页：需求与实施计划

## 目标与授权范围

根据用户“新增相似风格加载页面、全部资源加载完毕再展示简历”的要求，修改 `/resume` 的首开体验。沿用现有深黑、暖白、薄荷绿及衬线排版，不增加图片、字体或依赖。TSX 负责界面，加载与动画行为放在 TypeScript 文件。数据库、上传功能、身份验证不属于本次范围。

## 交互与验收标准

- 服务端 HTML 即包含全屏加载界面与正文的内联隐藏样式，防止 CSS 尚未到达时闪现正文；主内容保留布局用于图片和动画测量，但不可见、不可聚焦，页面不能滚动。
- 加载界面为个人作品集署名、衬线标题、薄荷绿进度线和准备状态。进度按已完成资源任务计数，不伪装成下载字节百分比；动画准备完成前不显示 100%。
- 等待所有页面图片成功加载并解码，包括原有非首屏懒加载图片、视频封面；等待字体、文档加载、样式表与 GSAP 动态模块。文档 load 后仍检查样式表实际存在，避免 CSS 失败时提前展示。
- 当前首页视频约 6.25 MB，须完整下载为 Blob，再交给视频元素解码首帧；不能仅用 `window.load`、`canplay` 或固定延时假定视频下载完成。
- 粒子标题完成采样、两组 GSAP 动画完成注册和布局刷新后才展示正文；粒子聚合、视频播放及 CSS 循环动效在展示时启动。
- 任一必要资源失败或等待超过 90 秒，仍不展示残缺正文；提示刷新重试。无 JavaScript 时显示启用提示。Canvas 不支持时采用现有完整语义文字替代粒子效果。
- 页面卸载时清理监听器、观察器、帧回调、未完成请求与视频 Blob URL。加载期间不因隐藏正文而取消图片加载或使动画无法测量。
- 保留语言切换、离屏视频暂停、滚动章节及原有交互。加载文案跟随现有中英语言设置。

## 文件职责、接口与状态

- `resume-loading.ts`：加载状态类型、事件名、带取消的资源就绪等待、图片解码、完整视频下载及准备完成条件；使用浏览器原生 API。
- `use-resume-loading.ts`：管理 `loading → preparing → ready`，失败进入 `error`；返回 `{ state, progress, retry }`。
- `resume-loader.tsx`：纯展示组件，接收状态、进度、语言、重试方法。
- `resume-portfolio.tsx`：在现有根节点内组合加载界面与被遮挡的正文，控制 `inert`、`aria-hidden` 和加载状态属性。
- `use-resume-gsap.ts`：资源就绪后注册已有动画，分别发出 motion/interactions 完成信号；保持浏览器内动态导入和 context 清理。
- `use-resume-motion.ts`、`use-resume-interactions.ts`：标记初始化完成；视频仅在正文展示后开始播放。
- `use-particle-title.ts`：采样完成通知，展示前暂停帧循环，展示时从散点开始聚合。
- `resume-loading.css`：独立加载样式，复用原有视觉令牌，限定加载期间的可见性、滚动与动画暂停规则。

原生自定义事件负责“资源完成”“动画准备”“正文展示”三个生命周期通知；根节点状态同时保留结果，避免监听注册时序造成漏信号。所有等待同时接收 AbortSignal，错误或卸载统一取消。
